# data-pipeline/ —— 成员4 · 数据/情报工程师

> 你的职责：给「出海情报雷达」供数——采数据、做向量化、做 RAG 检索。

## 我的工作（一句话）
整理目标市场情报数据（趋势/竞品/合规），做向量化 + RAG 检索，输出带来源的情报摘要。

## 目录结构（建议）
```
data-pipeline/
├── README.md
├── requirements.txt
├── app/
│   ├── main.py            # /data/intel/search /data/health
│   ├── loader.py          # 数据采集/整理
│   ├── embed.py           # 向量化
│   └── search.py          # RAG 检索
├── data/
│   └── markets/           # 各目标市场情报（结构化）
└── scripts/               # 采集脚本
```

## 依赖与被依赖
- **依赖**：成员1 的数据接口约定（`docs/03-接口规范.md` 第 3 节）。
- **被依赖**：成员1 的 backend 调用我；成员2 展示我的情报结果。

## 验收标准
- [ ] 提供至少 1–2 个目标市场的可用情报数据集。
- [ ] 检索服务能按查询返回相关情报摘要（含来源）。

## 我的任务清单
- [ ] 设计情报数据结构（市场/品类/合规/竞品）
- [ ] 采集整理第一批目标市场情报（可用公开数据 + 知乎 CLI）
- [ ] 实现向量化（嵌入模型 + 向量库）
- [ ] 实现 RAG 检索服务 `/data/intel/search`
- [ ] 补全情报并标注来源
- [ ] 准备演示用检索样例

## 怎么开始
先定一个小目标市场（如美国 + 日本）做端到端：`采集 → 整理 → 向量化 → 检索` 跑通一条，再扩展数据量。
