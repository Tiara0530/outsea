# 04 · 提交指南（最终验收）

## 一、作品验收标准（一个作品）

最终交付的是**一个可用的应用**，三个功能在其中可操作、可演示：

- [ ] 商品本地化：输入中文商品信息，输出目标市场多语言内容。
- [ ] 跨文化沟通：输入中文意图，输出目标市场话术/邮件。
- [ ] 出海情报：输入品类+市场，返回趋势/竞品/合规摘要。
- [ ] 前后端真实联通（非纯静态假页面）。
- [ ] 可一键部署 / 提供可访问地址。

## 二、提交材料清单

| 材料 | 负责 | 要求 |
|------|------|------|
| 项目代码（GitHub 仓库） | 全员 | 结构清晰、可运行、README 完整 |
| 部署/访问地址 | 成员5 | 公网可访问或提供部署说明 |
| Demo 视频 | 成员5 | 3 分钟内展示三个功能 + 亮点 |
| 项目说明/PPT | 成员5（牵头） | 痛点、方案、创新点、技术实现 |
| 报名与作品提交 | 成员1（组长） | 按官方 12.05–12.07 窗口提交 |

## 三、Demo 视频建议脚本（约 3 分钟）

1. （30s）一句话讲痛点：出海卡在语言/文化/情报。
2. （90s）演示三个功能各一个真实例子。
3. （40s）讲技术亮点：本地化≠翻译、生成+情报闭环。
4. （20s）讲团队分工与协作方式。

## 四、时间线（关键节点）

| 时间 | 事项 |
|------|------|
| 11.05–12.04 | 报名 + 开发（组队、定方案、编码、联调） |
| 12.04 前 | 功能冻结，进入测试与打磨 |
| 12.05–12.07 | 线上开幕式 & 提交作品 |

## 五、提交前检查（成员5 收口）

- [ ] 仓库 `main` 分支可一键运行。
- [ ] 无密钥/密钥文件被提交（`.gitignore` 生效）。
- [ ] README 与文档和实际一致。
- [ ] Demo 视频与部署地址在提交页正确填写。
