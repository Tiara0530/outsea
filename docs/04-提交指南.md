# 04 · 提交指南（最终验收）

## 一、作品验收标准（一个作品）

最终交付的是一个可用的「客商对接智能系统」，核心流程可操作、可演示：

- [ ] **发布需求**：需求方发布产品、规格、数量、收货地、预算、交期。
- [ ] **上架供给**：供给方上架资源/商品、规格、发货地、价格、MOQ、交期。
- [ ] **AI 匹配**：兼容性硬门槛 + 成本/利润/效率打分，给出排序与推荐组合。
- [ ] **建立连接**：需求方勾选供应商，生成意向单。
- [ ] 前后端真实联通（非纯静态假页面）。
- [ ] 可一键部署 / 提供可访问地址。

## 二、提交材料清单

| 材料 | 负责 | 要求 |
|------|------|------|
| 项目代码（GitHub 仓库） | 全员 | 结构清晰、可运行、README 完整 |
| 部署/访问地址 | 成员5 | 公网可访问或提供部署说明 |
| Demo 视频 | 成员5 | 3 分钟内展示完整撮合流程 + 亮点 |
| 项目说明/PPT | 成员5（牵头） | 痛点、方案、创新点、技术实现 |
| 报名与作品提交 | 成员1（组长） | 按官方 12.05–12.07 窗口提交 |

## 三、Demo 视频建议脚本（约 3 分钟）

1. （30s）一句话讲痛点：跨境 B2B 靠人工撮合，慢、贵、不透明。
2. （90s）演示主线：甲发布需求 → 系统匹配 a,b,c,d,e → 甲勾选 a,b,e → 生成意向单。
3. （40s）讲技术亮点：兼容性硬门槛 + 成本/利润/效率打分，为什么这样撮合更合理。
4. （20s）讲团队分工与协作方式。

## 四、时间线（关键节点）

| 时间 | 事项 |
|------|------|
| 11.05–12.04 | 报名 + 开发（组队、定方案、编码、联调） |
| 12.04 前 | 功能冻结，进入测试与打磨 |
| 12.05–12.07 | 线上开幕式 & 提交作品 |

## 五、提交前检查（成员5 收口）

- [ ] 仓库 `main` 分支可一键运行（`cd backend && python main.py`）。
- [ ] 无密钥/缓存文件被提交（`.gitignore` 生效，无 `__pycache__`）。
- [ ] README 与文档和实际一致。
- [ ] Demo 视频与部署地址在提交页正确填写。
