# 02 · 分工说明（五人 · 各自工作区 · 验收标准）

> 原则：**一人一个目录、一人一份职责、一个统一接口、最后合成一个作品。**
> 任何人只在自己的工作区提交代码；公共改动（docs、接口、根配置）走 PR 由组长合入。

## 总览表

| 成员 | 角色 | 工作区 | 一句话职责 | 主要交付物 |
|------|------|--------|-----------|-----------|
| 成员1 | 组长 · 后端架构 | `backend/` | 定架构、写 API、编排与联调 | 统一 REST API + 编排服务 |
| 成员2 | 前端工程师 | `frontend/` | 做界面、接 API | 三个功能页可用的 Web 应用 |
| 成员3 | AI/LLM 工程师 | `ai-engine/` | 写 Prompt、生成引擎 | Prompt 库 + 本地化/沟通引擎 |
| 成员4 | 数据/情报工程师 | `data-pipeline/` | 采数据、做 RAG | 情报数据 + 检索服务 |
| 成员5 | QA/DevOps/交付 | `deploy/` | 测试、部署、演示、提交 | 部署配置 + Demo 视频 + 材料 |

## 成员1 · 组长 · 后端架构（backend/）

**职责**
- 负责整体架构设计与技术选型落定。
- 定义并维护 `docs/03-接口规范.md`（这是全队联调的「合同」）。
- 实现 FastAPI 后端：统一入口、鉴权、请求编排、错误处理、统一响应格式。
- 调用 ai-engine 与 data-pipeline 的服务，汇总返回。
- 组织每日进度同步，解决跨模块阻塞，合入 PR。

**依赖**：无（先出接口规范，供全员并行开发）。

**被依赖**：成员2、3、4 都按成员1 的接口规范对接。

**验收标准**
- [ ] `/api/v1/health` 可访问。
- [ ] 三个核心接口 `localize` / `communicate` / `intel/search` 至少能用「假数据(mock)」跑通，前端可联调。
- [ ] 统一响应格式与错误码按规范实现。
- [ ] 联调后，三个功能均能从后端真实串联到引擎/数据。

## 成员2 · 前端工程师（frontend/）

**职责**
- 搭建 React + Vite + TypeScript 应用骨架。
- 实现首页 + 三个功能页：商品本地化、跨文化沟通、出海情报雷达。
- 按接口规范调用后端 API，处理加载态/错误态/结果展示。
- 关注交互与观感，便于 Demo 展示。

**依赖**：成员1 的接口规范（可先用 mock 并行开发）。

**被依赖**：成员5 需要前端的可演示版本录 Demo。

**验收标准**
- [ ] 应用可本地启动，页面完整。
- [ ] 三个功能都能输入并展示结果（先 mock，后接真接口）。
- [ ] 对接口异常有友好提示。

## 成员3 · AI/LLM 工程师（ai-engine/）

**职责**
- 负责模型选型与接入（官方 Token 补贴）。
- 编写并沉淀 Prompt 库：商品本地化、多语言沟通、语气本地化。
- 实现生成引擎：输入 → 本地化/沟通输出，输出格式标准化（JSON）。
- 定义目标市场的文化规则（语气、禁忌、表达习惯）。

**依赖**：成员1 的引擎接口约定。

**被依赖**：成员1 的 backend 调用引擎；成员2 展示其输出。

**验收标准**
- [ ] 给定中文商品信息，能稳定产出目标语言标题/五点/关键词（JSON 结构）。
- [ ] 给定中文意图，能产出目标市场的邮件/客服话术，语气符合本地习惯。
- [ ] 输出格式符合接口规范，无脏输出。

## 成员4 · 数据/情报工程师（data-pipeline/）

**职责**
- 设计情报数据结构（市场、品类、合规、竞品）。
- 采集/整理目标市场基础情报数据（可用公开数据 + 知乎 CLI）。
- 实现向量化与 RAG 检索，为「情报雷达」供数。

**依赖**：成员1 的数据接口约定。

**被依赖**：成员1 的 backend 调用情报检索；成员2 展示情报结果。

**验收标准**
- [ ] 提供一份可用的目标市场情报数据集（至少 1–2 个目标市场）。
- [ ] 检索服务能按查询返回相关情报摘要（含来源）。

## 成员5 · QA/DevOps/交付（deploy/）

**职责**
- 编写部署配置，把整套服务部署到知乎 AI Works（或等价平台）。
- 做端到端集成测试，记录并推动修复 bug。
- 录制 Demo 视频、整理路演 PPT 与提交材料。
- 收口 README 与 `docs/04-提交指南.md`，确保 12.07 前完成提交。

**依赖**：全员交付物。

**被依赖**：最终提交。

**验收标准**
- [ ] 一键部署脚本/配置可用，服务可公网访问。
- [ ] Demo 视频完整展示三个功能。
- [ ] 提交材料齐全，按时提交。

## 协作规则（必读）

1. **分支**：每人 `feature/<成员名>/<功能>` 分支，合入 `main` 走 PR。
2. **提交**：只改自己工作区目录；改 docs/根配置需在 PR 里说明。
3. **接口**：任何接口变更先改 `docs/03-接口规范.md` 并通知全员。
4. **每日同步**：每天在 Issue / 群内更新一次进度与阻塞。
5. **阻塞就喊**：卡住超过半天立刻找组长，不硬扛。
