# 03 · 接口规范（客商对接智能系统）

> 全队联调的「合同」。任何变更先改本文件并通知全员。
> 成员1（backend）为对外唯一入口；成员3、4 提供内部服务，由 backend 编排。

## 1. 通用约定

- 基础路径：`/api/v1`，HTTP + JSON（UTF-8）。
- 统一响应：

```json
{ "code": 0, "message": "ok", "requestId": "a1b2c3d4", "data": { } }
```

- 错误码：`0` 成功；`40001` 参数错误；`40101` 未授权；`40401` 资源不存在；`50001` 内部错误；`50002` 上游服务不可用。

## 2. 数据模型

**需求 Demand**

```json
{ "id": "D001", "buyerId": "jia", "product": "主机", "specs": "8核/32G", "quantity": 100, "deliveryAddress": "德国柏林", "budget": 50000, "deadline": "2026-12-15" }
```

**供给 Supply**

```json
{ "id": "S001", "supplierId": "a", "product": "主板", "specs": "ATX", "origin": "深圳", "price": 120, "moq": 50, "stock": 500, "leadTime": 10 }
```

**匹配结果 Match**

```json
{ "demandId": "D001", "supplyId": "S001", "score": 0.92, "dimensions": { "cost": 0.9, "profit": 0.95, "efficiency": 0.9, "compatibility": 0.93 }, "reasons": ["单价低", "交期满足", "规格兼容"] }
```

**意向单 Connection**

```json
{ "id": "C001", "demandId": "D001", "supplyIds": ["S001", "S002", "S005"], "status": "connected" }
```

## 3. 对外接口

### 3.1 发布需求
`POST /api/v1/demands` — 入参 Demand，返回创建后的 Demand。

### 3.2 上架供给
`POST /api/v1/supplies` — 入参 Supply，返回创建后的 Supply。

### 3.3 匹配推荐
`GET /api/v1/match/{demandId}` — 返回：

```json
{ "matches": [ { "supply": { ... }, "score": 0.92, "dimensions": { ... }, "reasons": [...] } ], "recommendedGroup": ["S001","S002","S005"] }
```

### 3.4 建立连接
`POST /api/v1/connections` — 入参 `{ "demandId": "D001", "supplyIds": ["S001","S002","S005"] }`，返回 Connection。

### 3.5 健康检查
`GET /api/v1/health` — 返回各服务状态。

## 4. 内部服务接口（backend ↔ 子模块）

### ai-engine（成员3 提供）
- `POST /engine/match`：入参 `{ "demand": {...}, "supplies": [...] }`，返回 `{ "matches": [...], "recommendedGroup": [...] }`。
- `GET /engine/health`

### data-pipeline（成员4 提供）
- `GET /data/samples`：返回演示用供需样例。
- `POST /data/eval`：入参匹配结果，返回评测指标。
- `GET /data/health`

## 5. 联调顺序

1. 成员1 先实现 mock 返回，前端可并行联调。
2. 成员3、4 按入参/出参实现内部服务。
3. 成员1 把 mock 替换为真实调用，端到端联调。
