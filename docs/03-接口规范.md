# 03 · 接口规范（客商对接智能系统 · 与代码一致）

> 本文件是后端实际实现的接口契约，代码见 `backend/main.py`、`backend/matching.py`。
> 任何改动先改本文件并通知全员。

## 1. 通用约定

- 基础路径：`/api/v1`，协议 HTTP + JSON（UTF-8）。
- 统一响应格式：

```json
{ "code": 0, "message": "ok", "requestId": "a1b2c3d4", "data": { } }
```

- 错误码：

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40001 | 参数错误 |
| 40101 | 未授权 |
| 40401 | 资源不存在（需求/供给/路径） |
| 50001 | 内部服务错误 |
| 50002 | 上游服务不可用 |

## 2. 数据模型

### 2.1 需求 Demand

```json
{
  "id": "D001",
  "buyerId": "jia",
  "product": "主机",
  "components": { "主板": "ATX", "显卡": "RTX 4060", "CPU": "LGA1700", "电源": "750W", "内存": "DDR5" },
  "quantity": 100,
  "deliveryAddress": "德国柏林",
  "budget": 50000,
  "deadline": "2026-12-20"
}
```

> `components` 的 key 是「品类」，value 是「需求方要求的规格关键字」。匹配时按此做兼容性判断。

### 2.2 供给 Supply

```json
{
  "id": "S001",
  "supplierId": "a",
  "category": "主板",
  "specs": "ATX B760",
  "origin": "深圳",
  "price": 150,
  "moq": 50,
  "stock": 300,
  "leadTime": 10
}
```

### 2.3 匹配项 MatchItem

```json
{
  "supply": { "...": "Supply 对象" },
  "score": 1.0,
  "dimensions": { "cost": 1.0, "profit": 1.0, "efficiency": 1.0, "compatibility": 1.0 },
  "reasons": ["规格匹配", "交期满足", "MOQ满足", "单价150"],
  "excluded": false
}
```

> `excluded: true` 表示「规格不兼容，已排除」，`score=0`，不参与推荐。

### 2.4 意向单 Connection

```json
{ "id": "C001", "demandId": "D001", "supplyIds": ["S001", "S002", "S005"], "status": "connected" }
```

## 3. 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/health` | 健康检查 |
| GET | `/api/v1/demands` | 需求列表 |
| POST | `/api/v1/demands` | 发布需求 |
| GET | `/api/v1/supplies` | 供给列表 |
| POST | `/api/v1/supplies` | 上架供给 |

## 4. 接口详情

### 4.1 健康检查
`GET /api/v1/health`
```json
{ "code": 0, "data": { "status": "up", "demands": 1, "supplies": 10 } }
```

### 4.2 需求列表 / 发布
`GET /api/v1/demands` → `data` 为 Demand 数组。

`POST /api/v1/demands`，请求体为 Demand（`id` 可省略，自动生成），返回创建的 Demand。

### 4.3 供给列表 / 上架
`GET /api/v1/supplies` → `data` 为 Supply 数组。

`POST /api/v1/supplies`，请求体为 Supply（`id` 可省略），返回创建的 Supply。

### 4.4 匹配推荐
`GET /api/v1/match/{demandId}`

```json
{
  "code": 0,
  "data": {
    "matches_by_category": {
      "主板": [
        { "supply": { "...": "Supply" }, "score": 1.0, "dimensions": { "cost": 1.0, "profit": 1.0, "efficiency": 1.0, "compatibility": 1.0 }, "reasons": ["规格匹配", "交期满足", "MOQ满足", "单价150"], "excluded": false },
        { "supply": { "...": "Supply" }, "score": 0.0, "dimensions": { "cost": 0, "profit": 0, "efficiency": 1.0, "compatibility": 0.0 }, "reasons": ["规格不匹配，已排除"], "excluded": true }
      ],
      "显卡": [ "...": "同上结构" ]
    },
    "recommendedGroup": ["S001", "S002", "S003", "S004", "S005"]
  }
}
```

> `matches_by_category`：每个品类内部按得分降序；`recommendedGroup`：每个品类得分第一的供给 id。

### 4.5 建立连接 / 意向单列表
`POST /api/v1/connections`，请求体：
```json
{ "demandId": "D001", "supplyIds": ["S001", "S002", "S005"] }
```
返回创建的 Connection（`status = "connected"`）。

`GET /api/v1/connections` → `data` 为 Connection 数组。

## 5. 匹配逻辑（`backend/matching.py`）

1. **兼容性硬门槛**：需求 `components` 里某品类的规格关键字，其所有 token 必须都出现在供给 `specs` 中，否则直接 `excluded`（不参与推荐）。
2. **三维打分**（仅在兼容候选中）：
   - 成本 cost：`单价 × 数量`，越低越好（同类内归一化）。
   - 利润 profit：`(单价×数量)/预算`，占比越低、利润空间越大（归一化）。
   - 效率 efficiency：交期是否满足截止日 + MOQ 是否满足数量，各 0/1 取平均。
   - 权重：`cost 0.45 / profit 0.20 / efficiency 0.35`。
3. **输出**：按综合分降序，`recommendedGroup` 取每类第一名。
