# 01 · 项目方案（Outsea 出海智能助手）

## 一、背景与痛点

中小外贸卖家 / 跨境团队出海普遍卡在三道门槛：

1. **语言门槛**：多语言商品页靠人工翻译，慢、贵、不地道。
2. **文化门槛**：直译常冒犯当地习惯，语气、表达、禁忌需要本地化适配。
3. **情报门槛**：目标市场趋势、竞品、合规要求分散，调研成本高。

## 二、解决方案

做一个「一句话出海」的 AI 工具：用户输入中文商品/业务信息，系统一次性产出「能直接用」的出海内容。

| 功能 | 输入 | 输出 |
|------|------|------|
| 商品本地化引擎 | 中文商品名 + 卖点 | 目标语言标题、五点描述、SEO 关键词（本地化改写） |
| 跨文化沟通助手 | 中文意图 + 目标市场 | 多语言邮件/客服话术，语气本地化 |
| 出海情报雷达 | 商品/品类 + 目标市场 | 趋势、竞品、合规要点速查摘要 |

## 三、技术架构

```
┌──────────────┐
│   frontend   │  React + Vite（成员2）
└──────┬───────┘
       │ REST /api/v1/*
┌──────▼───────────────┐
│       backend        │  FastAPI 统一编排（成员1）
└──┬──────────┬────────┘
   │          │
┌──▼────────┐ ┌▼───────────────┐
│ ai-engine │ │ data-pipeline   │
│ LLM/Prompt│ │ RAG 情报检索    │
│ (成员3)   │ │ (成员4)         │
└───────────┘ └────────────────┘
```

- **backend** 是唯一对外入口，负责鉴权、编排、把前端请求分发给 ai-engine / data-pipeline 并汇总返回。
- **ai-engine** 专注 Prompt 与生成逻辑；**data-pipeline** 专注数据与检索；两者互不直接依赖，通过 backend 串联。
- 成员5 在 `deploy/` 负责把整套服务打包、部署、测试、演示。

## 四、创新点

1. **本地化 ≠ 翻译**：内置目标市场文化规则（语气、禁忌、表达习惯），做到「懂当地」而非「字面转换」。
2. **生成 + 情报闭环**：本地化输出同时附带该市场的趋势/合规提示。
3. **低成本可复现**：纯 API + 官方 Token 补贴，不依赖自训模型，三天可交。

## 五、与官方赋能结合

- 使用官方 **Token 补贴** 接入大模型 API；
- 使用 **知乎 CLI** 做内容/情报输入；
- 部署到 **知乎 AI Works**；
- 刘看山 IP 素材仅当需要演示彩蛋时使用（本赛道非强制）。
