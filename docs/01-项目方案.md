# 01 · 项目方案（Outsea 客商对接智能系统）

## 一、背景与痛点

跨境 B2B 供需对接长期靠人工撮合，慢、贵、不透明：

- **需求方找供应商难**：跨语言、跨地区，比价、比交期、比规格全靠人工。
- **供给方获客难**：手里的资源/商品难以被精准的需求方发现。
- **撮合不透明**：成本、利润、效率、兼容性没有量化，决策靠经验。

## 二、解决方案

供需双方各自「发布需求 / 上架资源」，AI 按**成本、利润、效率、兼容性**为双方匹配最合适的客商，并撮合建立连接、完成对接。

## 三、三大核心模块（对应赛道关键词）

| 模块 | 关键词 | 说明 |
|------|--------|------|
| 需求发布 | 对外贸易 | 需求方发布：产品、规格、数量、收货地、预算、交期 |
| 供给上架 | 对外贸易 | 供给方上架：资源/商品、规格、发货地、价格、MOQ、库存、交期 |
| AI 匹配撮合 | 跨境协作 | 按成本/利润/效率/兼容性打分排序，推荐供应商组合，建立连接（意向单） |

## 四、演示主线（核心示例）

甲（需求方）要采购 N 台主机，输入要求后，系统从平台已上架的供应商中匹配出 a（主板）、b（显卡）、c（CPU）、d、e；甲勾选 a、b、e 作为供应，系统为其建立连接、生成意向单，完成对接。

## 五、匹配逻辑

- **输入**：一条需求 + 候选供给列表。
- **四维打分**：
  - 成本（cost）：单价 × 数量 + 跨境物流估算
  - 利润（profit）：预算 − 成本（需求方视角的余量）
  - 效率（efficiency）：交期、MOQ、发货地到收货地距离
  - 兼容性（compatibility）：规格是否匹配（如 CPU 是否匹配主板）
- **输出**：按综合分排序的供应商 + 每项打分理由 + 推荐组合。

## 六、技术架构

```
frontend（成员2：需求方端 + 供给方端）
        │  REST /api/v1/*
backend（成员1：数据模型 + API + 匹配编排 + 连接/意向单）
        ├── ai-engine（成员3：匹配打分 + 组合推荐）
        └── data-pipeline（成员4：样例数据 + 效果评测）
```

## 七、范围边界（Demo）

核心交付：**发布/上架 + AI 匹配推荐 + 建立连接（意向单）**。「最终交易」以意向单状态呈现，不做真实支付。

## 八、与官方赋能结合

- 模型 API（官方 Token 补贴）接入匹配打分与理由生成。
- 部署到知乎 AI Works。
- 知乎 CLI 可选（作为行业/价格参考数据来源）。
